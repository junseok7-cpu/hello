# 인수인계 문서 — 발전원별 AI 예측·관리 시스템

> 다른 AI(Gemini 등)가 이어서 작업할 수 있도록 지금까지의 작업을 정리한 문서다. 이 문서 전체를 먼저 읽고 시작한다.

## 0. 너의 역할과 일정
- 과목은 "인공지능과 디지털 사고"이고, 팀 프로젝트 주제는 **발전원별 AI 예측·관리 시스템**이다. 너는 팀의 **에너지 전문 관리자** 역할을 맡는다.
- 일정은 11/30 프로그램 취합·최종보고서·영상, **12/1 제출·발표**다.
- 발표는 파트별로 나눠 맡는다: ① 지열·수열 ② 화력·원자력·바이오 ③ 태양광·풍력·수력 ④ 종합 및 모델 생성.
- 저장소는 GitHub `junseok7-cpu/hello`, 브랜치 `claude/happy-dijkstra-ke4gum`이다. 모든 작업은 `energy/` 폴더에 있다.

## 1. 핵심 메시지 (발표 결론)
> "설비를 더 짓기 전에, 이미 있는 설비를 더 잘 알자."

- 발전 효율은 카르노·베츠·쇼클리–퀘이서 같은 물리 한계에 가까워졌고, 이제 과제는 **출력의 불확실성**이다.
- AI는 발전원마다 다르게 쓴다.
  - 날씨에 좌우되는 발전원(태양광): **하루 전 예측**
  - 출력이 일정한 발전원(연료전지): **평소와 다른 날 알림(이상탐지)**
  - 수요를 따라가는 발전원(화력): **추종 관계 분석**
- AI가 **할 수 없는 것**도 함께 밝힌다.
  - 물리 한계를 넘는 것
  - 변동 자체를 없애는 것
  - 계량되지 않은 71% 설비를 직접 관측하는 것
  - 정비 기록 없이 알림이 실제 고장인지 판정하는 것

### 데이터 문제와 보정 (`audit.py` → `results/data_audit.json`)
1. **중복 행**: 시도·시각이 겹치는 행이 66,976개이고, 그중 52,944개는 값이 서로 다르다. 중복을 제거해 806,408행 → 739,432행이 됐다.
2. **시각 기준 어긋남**: 관측 일사량이 대기권 밖 일사량보다 큰 경우가 27,566건이다. 시각 기준이 어긋난 것으로 본다.
3. **야간 발전량**: 해가 없는 시간에도 발전량이 찍힌다. ESS 방전으로 추정하며, 비중은 2021년 10.9% → 2024년 4.4%다.
4. **중부발전 단위 오류**: 2025년 1~6월 발전량이 1000배로 기록돼 ÷1000으로 고쳤다.
5. **설비용량 오기**: 인천연료전지 설비용량을 바로잡았다.
6. **계량 범위**: 데이터에 있는 태양광은 전체 30.6GW 중 **29.2%만 계량** 설비다.
7. **태안 이용률 단위**: ×1000으로 맞췄다.

## 3. 모델과 방법 (`analyze.py`, 344줄, 전체 실행 약 52초)

### 태양광 하루 전 예측 (주 모델)
- **모델**: LightGBM. 2023년 검증 데이터로 early stopping(100회)을 적용했다. 지역은 범주형으로 넣었다.
- **예측 대상**: 이용률(CF) = 발전량 ÷ 설비용량. 설비 증설 효과를 없애기 위해서다.
- **피처**
  - 시각·날짜의 sin/cos 변환
  - 단기예보에 있는 기상 항목: 기온, 습도, 풍속, 운량, 강수, 적설
  - 24시간 전·1주 전 이용률(lag24, lag168). 미래 정보 누출이 없다.
- **데이터 분할**: 학습 2020~22년, 검증 2023년, 시험 2024년. 평가는 **낮 시간만** 한다.
- **평가 지표**
  - nMAE, nRMSE: 설비용량 대비 %
  - Skill = 1 − 모델 오차 ÷ 기준 모델 오차
  - 기준 모델(Persistence)은 어제 같은 시각의 값이다.
- **예측 범위**: 분위수 회귀로 P10~P90을 구하고 split-conformal로 보정했다.

### 결과 (2024년 시험 데이터)

| 실험 | nMAE | nRMSE | Skill |
|---|---|---|---|
| 어제 값(기준) | 9.76 | 15.38 | 0 |
| 선형회귀 | 6.98 | 9.19 | 0.402 |
| **LightGBM(시드 3개 평균)** | **4.13** | **6.05(±0.01)** | **0.607** |
| 날씨 정보 없음 | 9.19 | 12.77 | 0.170 |
| 시간·지역만 | 10.39 | 13.83 | 0.101 |
| + 실측 일사량 | 3.80 | 5.58 | 0.637 |

- **발전량을 그대로 학습한 경우**: nRMSE 14.37%, 편향 −7.93%p. 이용률로 학습하면 편향이 +0.43%p로 해소된다.
- **예측 범위 포함률**: 보정 전 74.8% → **보정 후 80.4%**(목표 80%).
- **전력거래소 공식 예측과 비교(2024.12.2 하루)**: 공식 8.88%, 우리 모델 4.93%, 어제 값 8.36%.

⚠️ **꼭 함께 말할 한계**: 기상 입력은 **예보가 아니라 관측값**이다. 따라서 성능은 **상한선**이고, 실제 운영에서는 오차가 더 크다. 전력거래소와의 비교도 정답 날씨를 보고 한 결과다.

### 연료전지 이상탐지
- **방법**: 과거 28일 이용률 중앙값을 기준선으로 쓰고, MAD로 σ를 구한다.
- **알림 조건**: 기준선에서 3σ를 넘고 **동시에 15%p 넘게 하락**한 날만 알린다.
- **결과**: 5기 합계 **51건**. 통계 기준만 쓰면 날짜의 5.6~19.4%가 알림이 돼서 두 조건을 함께 걸었다.
- **한계**: 세종연료전지 연간 중앙값이 2023년 88.1% → 2026년 68.9%로 떨어졌다. 28일 기준선은 이런 장기 저하를 따라가 버려 놓친다.

### 태양광 성능 저하 후보
- 같은 날 같은 지역 발전소끼리 비교해 날씨 영향을 지웠다.
- 26곳에서 **272구간**을 찾았다.

### 화력·원자력 분석 (모델 없이 분석만)
- **수요와의 상관계수**: LNG 0.841, 석탄 0.621, 유류 0.488. LNG가 수요를 가장 잘 따라간다.
- **변동계수**: 수요 0.108, 석탄 0.171, LNG 0.271.
- **태안 이용률**: 73.2%.
- **한빛 5호기 이용률**: 2020년 31.0%, 2021년 18.7%, 2023년 16.0%.
- **설계수명 만료**: 2030년까지 10기.

## 5. 발전원별 모델 현황

| 발전원 | 상태 | 이유 |
|---|---|---|
| 태양광 | 예측 모델 완성 | 시간별 데이터와 기상 데이터가 있음 |
| 연료전지 | 이상탐지 완성 | 출력이 일정함 |
| 화력 | 상관 분석만 함 | **예측 모델 추가 가능**(6-1 참고) |
| 풍력 | 없음 | **이상탐지 추가 가능**. 발전소 위치 바람 데이터가 없어 예측은 약함 |
| 소수력 | 이용률 분석만 함 | **이상탐지 추가 가능**. 강수량에 따른 변동을 고려해야 함 |
| 원자력 | 추이 분석만 함 | 연간 데이터뿐이라 학습 불가 |
| 지열·수열·바이오 | 설계안만 있음 | 데이터 없음. 국내 상업 지열발전소도 없음 |

## 6. 남은 작업 (우선순위 순)
1. **(선택) 화력 LNG 일별 발전량 예측**
   - 데이터: `fuel_daily_region`과 `demand_hourly`가 겹치는 2018~2021년
   - 피처: 그날 수요(일 합계·최대), 요일, 월의 sin/cos, 전일·1주 전 LNG 발전량
   - 학습 2018~2020년, 시험 2021년. 어제 값 기준 모델과 Skill로 비교한다.
2. **(선택) 풍력·소수력 이상탐지**: `analyze.py`의 연료전지 이상탐지 블록(170~178행 근처)을 해당 설비에 똑같이 적용한다.
3. 1·2를 하면 보고서, pptx, 미리캔버스에 페이지를 추가한다.
4. **팀이 직접 할 일**
   - 표지·끝 페이지에 팀원 이름 넣기
   - 데이터 제공기관 명칭 확인(공공데이터포털, 한국중부발전, 전력거래소, 한국수력원자력 등)
   - 파트별 발표 대본 정리
   - 11/30 영상 제작
5. 목차(2페이지)의 4파트 항목에 "코드 구현"을 넣을지 정한다.

## 7. 지켜 온 원칙
- 수치는 results.json에 있는 값만 쓴다. 자료마다 다르게 나오는 수치(개업 연도, 비율 등)는 넣지 않는다.
- 성능을 말할 때는 항상 **"관측 기상을 넣은 상한선"**이라고 밝힌다.
- 이상탐지는 "고장 감지"가 아니라 **"이상 후보 알림"**이라고 표현한다. 정비 기록과 대조하지 않았기 때문이다.
- 쉬운 한국어로 쓰고, 전문용어는 처음 나올 때 풀어 쓴다.
